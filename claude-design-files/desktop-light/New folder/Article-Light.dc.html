Closures, explained

How a function keeps the variables around it alive, and why that is useful.

By [Author name]Published Oct 2, 2026Updated Oct 8, 20266 min readjavascriptscope

What a closure is#

A closure is a function bundled together with the variables from the scope where it was created. When the function runs later, it can still read and change those variables, even if the outer function has already returned.

Every function in JavaScript is a closure. The behavior only becomes visible when you return a function, or pass it somewhere that outlives the scope it came from.

counter.js
function makeCounter() {
  let count = 0;
  return () => {
    count += 1;
    return count;
  };
}

const next = makeCounter();
next(); // 1
next(); // 2

Each call to makeCounter creates a new count. Two counters made from two calls never share state.

TipClosures capture variables, not their values at that moment.

Why it matters#

Closures let you keep private state without a class, build functions that remember their configuration, and write event handlers that know which item they belong to.

Private state#

Nothing outside makeCounter can reach count. The only way to change it is through the returned function.

WarningWith var in a loop, every callback shares one variable. Use let to get a fresh one per iteration.
